# MIRACL 한국어로 잰 결합 손실 (2026-11-14)

공개 벤치마크 MIRACL의 한국어 dev 질의 213개를 줄인 말뭉치에 넣고, F1의 하네스와 F-7 도구로 쟀다. 원어민이 답을 모르고 쓴 질문과 사람의 관련성 판정을 쓴다. F1 묶음(세션 초안 32개)이 보여 준 문제가 자연스러운 질문에서도 일어나는지 보려는 것이다.

**이 측정은 기본값을 바꾸는 근거가 아니다(규칙 10.3).** 결합 방식을 고르는 일은 F2에서 하고, 그때는 아래의 조정용 질의만 본다.

## 결론

1. **위키 사실 질문에서 정답 구절과 낱말이 전혀 안 겹치는 질문은 거의 없다(213개 중 1개).** 일부만 겹침(0.5 미만) 92개(43%), 많이 겹침 120개. F1 묶음(안 겹침 13/32)은 일부러 어렵게 만든 것이라 비율을 대표하지 않는다. 이 비율은 "위키 사실 질문에서의 비율"이고, 한국어 바이그램이 겹침을 부풀린다.
2. **벡터 검색이 상위 5개 안에 찾은 정답을 기본 하이브리드가 버리는 일이 자연스러운 질문에서도 일어난다.** KoEn 5천 34개(벡터가 찾은 196개 중 17%), BGE-m3 5천 31개(199개 중 16%), KoEn 1.5만 33개(176개 중 19%). 버려지는 질문은 대부분 일부만 겹치는 질문이다(KoEn 5천 34개 중 29개).
3. **후보 방식(벡터 1위 자리 보장, 정규화 선형 0.5)은 합계로는 기본값보다 낫지만, 잃는 질문이 없다는 것은 이 자료에서 성립하지 않는다.** 말뭉치가 커지면 잃는 질문이 늘고 방식 사이의 순서가 바뀐다. KoEn에서 정규화 선형 0.5 / 벡터 1위 자리 보장 / RRF 0.5는 5천에서 184 / 183 / 182, 1.5만에서 171 / 173 / 178이고, 정규화 선형 0.5는 1.5만에서 13개를 잃는다.
- **단서:** 두 모델 모두 MIRACL train으로 미세조정됐다(아래 "확인한 것"). 벡터 검색 수치와 벡터 비중을 올리는 방식의 이득이 실제보다 크게 나왔을 수 있다.

## 원인: 기본 하이브리드는 BM25 상위 20개 안에서만 순서를 바꾼다

코드(`rust_builder/rust/src/api/hybrid_search.rs` `compute_hybrid_rrf_scores`, `lib/src/internal/defaults.dart`)와 덤프로 확인했다.

- `ask`는 topK 5를 부르고, 컬렉션 필터가 있으면 후보를 4배(목록마다 20개) 가져온다.
- 결합 점수는 순위만 쓴다: `0.2/(60+벡터 순위) + 0.8/(60+BM25 순위)`.
- 벡터 1위이고 BM25 목록에 없는 청크는 `0.2/61 ≈ 0.0033`, BM25 20위(꼴찌)이고 벡터 목록에 없는 청크는 `0.8/80 = 0.0100`이다. BM25 목록이 다 차 있으면 벡터에만 있는 청크는 상위 5개에 들 수 없다(경계는 벡터 가중치 61/141 ≈ 0.433, F-7).
- **BM25 목록은 거의 항상 다 찬다.** 한국어는 바이그램으로 토큰을 만들어 흔한 조각 하나만 맞아도 목록에 든다. 세 실행 모두 213개 중 212개 질의에서 BM25 목록이 20개였다.
- 그 결과, 세 실행 모두 기본 하이브리드 상위 5개 1,065자리 중 **1,060자리가 BM25 목록에 있던 청크**였고, 벡터에만 있던 청크는 5자리(BM25 목록이 덜 찬 한 질의)뿐이었다. 벡터 검색은 BM25가 고른 20개의 순서만 바꾼다.
- MIRACL에서 각자 상위 5개 안에 정답을 넣은 질의 수는 벡터 196 / BM25 153(KoEn 5천)이다. **더 약한 쪽에 0.8을 준다.**
- 기본값의 내력: 0.5/0.5에서 커밋 `5f506d7`(2026-02-14, "improve hybrid retrieval quality")로 0.2/0.8이 됐다. 커밋에 근거는 적혀 있지 않다. W1은 "좋은 값이 모델마다 반대"라는 이유로 바꾸지 않았다. 기본 모델 MiniLM은 영어 전용이라 한국어에서 벡터가 약하고, 0.2/0.8이 그 경우를 지킨다. 기존 F-7 덤프를 언어별로 다시 세면, 80개 묶음 MiniLM의 벡터 비중 0.2 → 0.6에서 한국어 32개는 27 → 8, 영어 32개는 29 → 30이다(나머지 16개는 언어 표기가 en/ko가 아니라 이 집계에서 빠졌다). **0.2/0.8은 "한국어 문서에 영어 전용 기본 모델"을 지키는 대가로 다국어 모델의 벡터 검색을 거의 쓰지 못하게 한다.**

## 다른 구현과 비교 (2026-11-14 문서·소스에서 확인)

| 구현 | 결합 | 기본 무게 |
|---|---|---|
| LangChain `EnsembleRetriever` | RRF, `c = 60` | 모든 검색에 같은 무게(소스의 `_set_weights`) |
| Elasticsearch RRF retriever | RRF, `rank_constant` 60 | 같은 무게(무게 설정 없음). `rank_window_size`는 요청의 `size` |
| Qdrant hybrid query | RRF(k 기본 2) 또는 DBSF | 같은 무게. 문서는 평가셋으로 조정하라고 권한다 |
| Weaviate hybrid | Relative Score Fusion(v1.24부터 기본) | `alpha` 0.75(벡터 75%) |
| 이 엔진 | RRF, k 60 | 벡터 0.2 / BM25 0.8 |

MIRACL 논문(arXiv 2210.09984, Table 2, dev nDCG@10): 한국어 BM25 0.419, mDPR 0.419, 두 점수를 섞은 Hybrid 0.609. 평균은 0.393 / 0.415 / 0.578. 제대로 섞으면 어느 한쪽보다 크게 좋아지는 것이 보통이다. 이 엔진은 섞은 결과(KoEn 5천 167)가 자기 벡터 검색(196)보다 나쁘다.

### 읽는 법

- 질의 213개에서 서너 개 차이는 잡음일 수 있다(HNSW를 새로 만들 때마다 한두 질의가 달라진다. 방식 비교는 같은 덤프 위라 이 영향이 없다).
- 기본값과의 차이는 일부 겹침 질의에서 나온다. 많이 겹치는 질의는 기본값이 이미 거의 다 맞힌다(114/120).
- 말뭉치를 세 배로 늘리면(5천 → 1.5만) 벡터 검색은 196 → 176으로 떨어지지만 BM25는 153 → 150이다. 기본값의 결과는 거의 같다(167 → 165). 늘어난 방해 구절은 대부분 무작위 구절과 같은 문서의 구절이다.
- 1.5만에서는 기본값 상위 5개 중 판정이 없는 구절이 17.4%다(5천 8.3%). 같은 문서의 판정 안 된 구절이 사실은 정답일 수 있어, 1.5만의 수치는 그만큼 덜 믿을 만하다.
- "뚜렷할 때만 보장"은 이 자료에서도 무조건 보장보다 이득이 작다. 기준값이 모델마다 다르다(F-7과 같다).

## 확인한 것

- **덤프가 엔진 결과를 재현한다.** 질의별 정답 순위(첫 긍정 구절의 텍스트 기준)를 엔진과 비교해, 가중치 다섯 × 두 조건에서 KoEn 5천 2,125/2,130, BGE-m3 5천 2,126/2,130, KoEn 1.5만 2,126/2,130이 같다. 다른 경우는 모두 BM25 점수 동점이 있는 질의였고(엔진은 동점 순서를 `HashMap`에서 정한다), 가중치 0.4와 0.6에서만 생겼다. **기본값(0.2)은 세 실행 모두 213개 전부 같다.**
- **모델의 학습 자료:**
  - BGE-m3 논문(arXiv 2402.03216) 자료 절: 영어·중국어 외 언어는 Mr. TyDi와 MIRACL의 학습 자료를 쓴다.
  - KoEn-E5-Tiny(`exp-models/dragonkue-KoEn-E5-Tiny-ONNX`)의 바탕 `intfloat/multilingual-e5-small` 모델 카드: 2단계 미세조정 자료에 MIRACL(16개 언어, 4만 쌍)과 Mr. TyDi가 있다. KoEn 자체의 추가 학습 자료 구성은 카드에 "dragonkue/snowflake-arctic-embed-l-v2.0-ko와 같은 자료"로만 적혀 있어 확인하지 못했다.
- 색인: 넣은 구절 수와 색인된 source 수가 같고(5,000 / 15,000), 긍정 구절은 모두 색인됐다. 구절 419개(5천) / 1,117개(1.5만)가 청크 여러 개로 나뉘었고, 그중 긍정 구절은 43개다. source 단위 채점이라 나뉘어도 맞힌 것으로 센다.
- 제목을 빼고 본문만으로 세어도 겹침 분포는 같다(안 겹침 2, 일부 91, 많이 120, 중앙값 0.5). 질의 213개 중 179개는 제목과 토큰 하나 이상을 공유한다.

## 확인하지 못한 것과 한계

- **BGE-m3 1.5만:** 첫 실행이 색인 도중(13,757/15,000) 하네스의 90분 제한에 걸려 실패했다. `flutter drive`가 0으로 끝나 `run_meta.json`에 성공으로 적혔던 것은 수집 스크립트가 고쳤다(`cb77855`). 제한을 240분으로 늘려 다시 돌리는 중이다.
- **답 없는 질문:** MIRACL에는 없다. F1 묶음의 8개가 유일하다.
- **문서 종류:** 위키뿐이다. 모든 문서가 짧은 구절이라 긴 문서 여러 개인 실제 사용과 다르다(구절을 문서 단위로 이어 붙인 실행은 하지 않았다).
- **질문 종류:** 위키 사실 질문이라 고유명사가 많다. 개인 문서에 채팅하듯 묻는 `ask`와 다를 수 있다.
- **절대값:** 150만 구절을 5천/1.5만으로 줄였으므로 논문의 수치와 비교하지 않는다. 같은 묶음 안의 방식 비교에만 쓴다.
- **MiniLM:** 한국어 판정에서 뺐다(언어별 모델 안내 방침). 돌리지 않았다.
- **기기:** Mac 한 대.
- **조사·어미만 겹친 경우**를 따로 나누지는 못했다.
