# F-8 F1 보고서: 검색 평가 기준선 (2026-11-13)

`docs/milestones.md` F1의 마지막 단계다. F-0~F-7의 결과를 한곳에 모아 이후 검색 변경이 기댈 기준선을 적는다. 결합 방식이나 기본값을 바꿀지(F2)는 이 보고서를 보고 따로 정한다. **이 보고서의 어떤 수치도 기본값을 바꾸는 근거가 아니다**(규칙 10.3).

## 한 줄 요약

- 기존 평가 자료는 낱말이 겹치는 쉬운 질의만 잰다. 80개 묶음은 회귀 확인용으로 남겼다(F-0).
- 실제 `ask` 조건(topK 5, 후보 20)은 README 수치(topK 100의 `@10`)보다 0.04~0.06 낮다(F-3).
- 낱말이 안 겹치는 질문에서는 다국어 모델의 벡터 검색이 찾은 정답 대부분이 기본 하이브리드에서 사라진다. KoEn 11/14 → 4/14, 검수 반영 뒤 10/13 → 4/13(F-2).
- 이 현상은 가중치 문제라기보다 구조다. 후보 20개에서 벡터 가중치가 61/141(≈0.433) 이하면 벡터에만 있는 청크는 BM25 단독 청크를 넘지 못한다(F-7).
- 평가는 한 명령으로 돌고, 규칙 9 항목이 결과 파일에 자동으로 들어간다. 새 클론에서 MiniLM 기준값이 재현됐다(F-4/F-5).

## F2로 넘기는 것

F1의 범위 밖이라 고치지 않았다. 마일스톤 문서의 후보 목록에 적었다.

1. **`ask` 조건에서 벡터 결과가 구조적으로 밀린다.** 위 F-7의 경계. 결합 방식(정규화 선형, 자리 보장, 모델별 가중치)을 고를 때 F1 묶음과 80개 묶음 둘 다에서 기본값보다 나빠지지 않는지 본다.
2. **`ask` 조건의 HNSW 손실.** `ef_search = max(100, top_k × 5)`라 `ask`는 ef 100이다. vector_only에서도 topK 100에서 찾던 정답을 놓치는 질의가 있다(`f2_stage1.md`). exact scan과의 비교는 아직 하지 않았다.
3. **답 없는 질문의 신호.** RRF 점수는 순위만 반영해 기준값이 되지 못한다. 점수 기준값이 필요하면 앱에 두는 값이다(규칙 10.2).

## 이 기준선의 한계

- **F1 묶음은 세션 초안이다.** 2026-11-14에 원문 대조 검수(수정 6, 경미 5)를 반영했지만, 그 검수가 사람이 한 것이 아니라고 적고 있어 작성자는 `session_draft`다. 검수표는 `f2_review_sheet.md`. 사람이 확정하면 `session_draft+human_review`로 바꾸고 질의를 100~150개로 늘린다. 검수가 남긴 의견: 영어 겹침에 불용어(the, of)가 같이 세이고, 한국어 겹침은 바이그램으로 부풀며, 위키 문서를 겨냥한 답 없는 질문이 없다.
- 질의 32개(답 있음)는 작다. 기본값 변경의 근거가 되려면 묶음을 늘려야 한다.
- 측정 기기는 Mac 한 대다. iPhone·Android의 `ask` 조건은 재지 않았다.
- F-0 정답 라벨 표본 40개(`f0_label_sample.md`)도 세션 판독이다.
