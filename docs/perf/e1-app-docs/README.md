# E1: 앱 형태 문서로 잰 하이브리드 무게

`docs/milestones.md` E1의 기록이다. F2는 하이브리드 검색(`ask`: 상위 5개, 목록마다 후보 20개)의 기본 무게(벡터 0.2 / BM25 0.8)가 BM25 후보에 없는 정답을 버리는 "벽"을 찾았고, KoEn-E5-Tiny 레시피에 0.5/0.5를 권했다([`../f2-fusion/README.md`](../f2-fusion/README.md)). 그 근거 자료는 위키백과, 공개 보고서, 의학·생명과학 논문 초록이었다. 이 문서는 앱이 실제로 넣을 법한 문서(제품 도움말, 앱 FAQ·릴리스 노트, 사내 규정·회의록, 긴 PDF)와 질문으로 같은 비교를 다시 한 결과다. 엔진 기본값과 레시피 값은 바꾸지 않았다.

> **예비 결과.** 질문 120개는 세션이 쓴 초안(`author: session_draft`)이고 아직 사람이 검수하지 않았다. 검수표는 [`review_sheet.md`](review_sheet.md)다. 검수에서 질문이 바뀌면 수치를 다시 낸다.

## 결론

- **KoEn-E5-Tiny: 0.5/0.5가 기본값보다 낫다. 레시피와 같은 방향이다.** 답 있는 90개 중 66 → 76(+11/−1, 부호 검정 p ≈ 0.006). 영어 31 → 35, 한국어 35 → 41이고, 조정용 절반(32 → 37)과 확인용 절반(34 → 39) 모두 같은 방향이다. 0.6/0.4는 이 자료에서 0.5/0.5와 질문별로 같다(76).
- **MiniLM(기본 모델): 합계는 같고 언어별로 갈린다.** 56 → 56(+5/−5). 영어는 32 → 35(+4/−1)로 늘고 한국어는 24 → 21(+1/−4)로 준다. MiniLM은 영어 전용이라 한국어 벡터 검색이 거의 못 찾는다(벡터만 2/45). F2에서 본 모양과 같아서, 이 결과도 MiniLM의 기본값을 바꿀 근거가 되지 않는다.
- **BGE-m3(참고): 0.5/0.5가 뚜렷이 낫다.** 67 → 78(+12/−1, p ≈ 0.003). F2의 영어 논문 자료에서는 0.2와 0.5가 같았던 모델이다(429 대 429). 레시피를 만들지 않은 모델이라 기록만 한다.
- **얻은 몫은 거의 모두 "다른 낱말로 묻는 질문"에서 나온다.** 낱말이 겹치는 질문은 세 모델 모두 기본값에서 이미 거의 다 맞고(영어 19/20, 한국어 KoEn·BGE-m3 20/20), 0.5/0.5에서 잃은 것은 모델마다 0~1개다.
- **벽은 이 자료에도 있다.** 영어 질문은 60개 모두 BM25 20개 목록이 찼고, 목록이 찬 질문에서 기본값 상위 5개는 세 모델 모두 100% BM25 후보였다.
- **답 없는 질문은 RRF 점수로도, 벡터 유사도 하나로도 가를 수 없다.** 30개 모두 상위 5개가 채워져 나왔고, 대부분 앱 문서·사내 문서의 비슷한 주제 청크가 1위였다. 벡터 1위 유사도도 답 있는 질문과 많이 겹친다(아래 표).
- **확신: 중간.** 방향(KoEn·BGE-m3에서 0.5가 낫고, MiniLM 한국어에서 잃음)은 세 갈래 나눔(언어, 조정/확인, 문서 종류)에서 같은 쪽이라 높게 본다. 크기는 낮게 본다. 질문을 세션이 썼고 문서 일부(직접 쓴 24개)도 같은 세션이 써서, "다른 낱말로 묻는 질문"이 실제 사용자 질문보다 벡터 검색에 유리하게 쓰였을 수 있다. 답 있는 질문이 90개뿐이라 언어별 차이는 대부분 통계로 가를 수 없다.

## 벽: 이 자료에서도 BM25 목록이 차는가

| 실행 | BM25 20개 목록이 찬 질문 (영어 / 한국어, 각 60) | 찬 질문의 기본값 상위 5개 중 BM25 후보 | 벡터만 맞고 기본값 틀림 (그중 BM25 목록 참) | 그중 0.5 / 0.6이 되찾음 |

## 답 없는 질문 (30개)

| 실행 | 기본값 1위의 문서 종류 (직접 쓴 / GNOME / PDF), 영어 · 한국어 | BM25 20개 목록이 찬 질문 | 벡터 1위 유사도 중앙값 (답 없음 / 벡터로 맞힌 답 있음) | 답 없음 중 "벡터로 맞힌 질문의 최솟값" 이상 |
|---|---|---|---|---|
| MiniLM | 10/2/3 · 11/2/2 | 영어 15/15, 한국어 6/15 | 영어 0.465 / 0.541, 한국어 0.710 / 0.619 | 영어 11/15, 한국어 14/15 |
| KoEn | 11/2/2 · 13/2/0 | 같음 | 영어 0.537 / 0.592, 한국어 0.474 / 0.540 | 영어 11/15, 한국어 12/15 |
| BGE-m3 | 10/2/3 · 14/1/0 | 같음 | 영어 0.553 / 0.649, 한국어 0.571 / 0.638 | 영어 11/15, 한국어 15/15 |

- 유사도는 1 − (엔진이 돌려준 벡터 거리)다.
- 30개 모두 상위 5개가 채워져 나왔다. 0.2에서 0.5로 바꾸면 1위 문서가 30개 중 4~6개에서 바뀌었다(MiniLM 5, KoEn 6, BGE-m3 4). 표의 종류별 수는 거의 그대로다.
- 1위는 30개 모두 같은 언어의 문서였고, 대부분 비슷한 주제의 앱·사내 문서였다(KoEn 예: "What is the warranty period for the Lumo Hub?"에 Lumo 허브 Wi-Fi 문제 해결 문서, "해외 출장 숙박비 한도는 얼마인가요?"에 국내 출장비 정산 규정, "출장 갈 때 택시비도 정산되나요?"에 같은 규정). 2026-11-09 게임 가이드 연동에서 본 것처럼, 작은 생성 모델이 이런 가까운 문서로 답을 지어낼 수 있다.
- 벡터 1위 유사도는 답 있는 질문과 많이 겹친다. 답 없는 질문의 70~100%가 "벡터로 맞힌 답 있는 질문 중 가장 낮은 유사도"보다 높았다. 유사도 기준값 하나로 거르면 답 있는 질문을 함께 버린다. 이 측정으로는 거르는 신호를 정할 수 없고, 후보 목록의 "관련 없는 질문 거르기 신호"에 근거로 남긴다.

## example 앱

E1과 같은 PR로 example 앱을 바꿨다(범위는 `docs/milestones.md` E1).

- **모델 선택:** `--dart-define=EXAMPLE_MODEL=minilm|koen`. Model Pack(`assets/models/<이름>/model-pack.json`)으로 초기화한다. KoEn이면 레시피대로 `defaultVectorWeight: 0.5, defaultBm25Weight: 0.5`를 넣고, MiniLM은 엔진 기본값을 쓴다. 모델마다 DB 파일을 따로 쓴다. 상태 카드에 모델, 언어, 차원, 무게를 보인다.
- **"App docs" 화면:** E1 문서 56개를 `e1_app_docs` 컬렉션에 넣고(하네스와 같이 자산을 파일로 복사해 `addDocumentFromFile`), 질문 120개를 언어·유형별로 고르거나 직접 입력해 상위 5개를 본다. 무게(앱 기본, 0.2/0.8, 0.5/0.5, 0.6/0.4, 벡터만, BM25만)를 바꿔 볼 수 있고, 목록의 질문이면 정답이 상위 5개에 들었는지 표시한다. 검색은 하네스의 `ask` 조건과 같은 `searchMeta(topK: 5)`다.
- **`example/README.md`:** 모델 준비 안내를 Model Pack과 KoEn 레시피로 고쳤다(전에는 BGE-m3를 curl로 받는 안내였다).
- **앱 확인:** `example/integration_test/e1_app_docs_parity_test.dart`가 앱 코드로 문서를 넣고 질문 120개 × 무게 6개를 돌려, 결과를 하네스 덤프와 비교한다([`scripts/e1/compare_app_parity.py`](../../../scripts/e1/compare_app_parity.py)). 결과는 아래에 채운다.
