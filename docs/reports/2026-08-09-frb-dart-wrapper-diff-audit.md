# FRB Dart wrapper diff audit — canonical B versus HEAD A

**판정: 승인 후 canonical B의 13개 wrapper는 채택해야 한다.** 다만 실제
ABI/content-hash 계약은 이미 HEAD의 핵심 FRB 4개 파일과 일치하므로, 이 13개만
놓고 보면 즉시 런타임 호환성을 복구하는 변경은 아니다. `loadedHnswNodeCount`의
공개 편의 wrapper 1개와 생성기 정규화 결과를 반영하는 작업이다. 그러나 이번
릴리스에서 **canonical codegen zero-diff를 조건으로 삼는다면**, 이 cohort의
채택과 별도 범위의 추가 생성물 정리는 hosted consumer 검증 전에 끝나야 한다.

기존 working-tree C는 이 보고서에서 전혀 채택하지 않는다. 특히 C의 핵심 FRB
4개 파일은 `-394558992`/누락된 dispatcher 상태여서 B/HEAD의
`-941343322` 계약과 호환되지 않는다.

## 전체 tracked-file 비교에서 발견한 경계 사항

요청된 13개는 FRB API wrapper cohort다. 그러나 `git archive HEAD` 전체를 B와
파일별 비교하면 다음도 달랐다.

1. **codegen이 함께 쓴 추가 generated 파일 5개**: `error.freezed.dart`
   (+680/-905), `ingest_metrics.dart` (+2/-2), `migration_meta.freezed.dart`
   (+268/-340), `tokenizer.dart` (+4/-3), `user_intent.freezed.dart`
   (+392/-461). 앞의 3개 `*.freezed.dart`는 FRB wrapper가 아닌 Freezed 생성물이다.
   이 보고서는 단일 목표에 따라 의미 판독 대상에는 넣지 않았지만, 현재 명령의
   **완전한 zero-diff**를 요구한다면 승인 세션에서 이 5개도 별도 검토해야 한다.
2. `example/pubspec.lock`은 B 준비 중 `flutter pub get`이 transitive
   `crypto 3.0.7` 8줄을 추가한 결과다. codegen 채택 목록에는 포함하지 않는다.

따라서 “13개만 codegen zero-diff”와 “명령 실행 후 모든 tracked file zero-diff”는
동일한 조건이 아니다. 후자는 13개에 위 5개를 더한 18개 codegen 산출물의 별도
승인이 필요하다. 이 발견은 기존 12번째 보고서가 관찰한 13-wrapper cohort를
부정하지 않지만, 전체-tree zero-diff 주장에는 이 경계를 명시해야 한다.

## 릴리스 판정과 승인 경계

- **B 13개는 canonical 생성물로 채택 권고**: 자동생성 header와 성공한 B run이
  뒷받침한다. 특히 `hnsw_index.dart`는 `ffaddd4` Rust 원본을 public Dart API에
  정확히 노출한다.
- **ABI/hosted consumer 기능만의 관점**에서는 이 wrapper cohort가 기존 native
  binary의 content hash나 dispatcher를 바꾸지 않으므로, 긴급 ABI 복구 blocker는
  아니다.
- **이번 릴리스에서 full canonical codegen zero-diff를 release gate로 적용한다면**
  후속 cleanup으로 미룰 수 없다. 13개 cohort와 위 5개 추가 generated 파일을
  별도 승인·검토하여 clean committed HEAD에서 재생성 zero-diff를 증명한 뒤
  hosted-consumer 검증으로 넘어가야 한다.
- **13개 cohort의 최소 채택 목록**은 이 보고서의 hash 표에 있는
  `lib/src/rust/api/` 하위 13개 파일뿐이다. full-command zero-diff의 최소
  generated 목록은 여기에 `error.freezed.dart`, `ingest_metrics.dart`,
  `migration_meta.freezed.dart`, `tokenizer.dart`, `user_intent.freezed.dart`를
  더한 18개이며, `example/pubspec.lock`은 제외한다.
- 현재 dirty C는 이 13개를 모두 다른 내용으로 수정하고 있다. 다음 승인 세션은
  먼저 사용자 변경을 외부 patch/stash 등으로 **소유자 확인 하에 보존**한 뒤,
  clean committed HEAD에서 B를 재생성하고 결과를 review해야 한다. 이 세션은
  C를 수정·format·stage·commit하지 않았다.

다음 승인 없이는 generated 파일을 적용하지 않는다. push, PR, merge, tag, yank,
publish는 수행하지 않았다.
