# 상태 관리

상태 관리(state management)는 그래픽 사용자 인터페이스에서 텍스트 필드, 제출 버튼, 라디오 단추 등과 같은 하나 이상의 사용자 인터페이스 컨트롤의 상태를 관리하는 것을 말한다. 이러한 사용자 인터페이스 프로그래밍 기법에서 하나의 UI 컨트롤 상태는 다른 UI 컨트롤의 상태에 의존한다. 예를 들어, 상태 관리되는 UI 컨트롤인 버튼은 입력 필드에 유효한 입력값이 있을 때 활성화 상태가 되고, 입력 필드가 비어 있거나 유효하지 않은 값이 있을 때는 비활성화 상태가 된다. 애플리케이션이 커짐에 따라, 이는 결국 가장 복잡한 개발 문제 중 하나가 될 수 있다.
이는 특히 페이지의 특정 메시지나 양식의 상태가 현재 페이지 외부의 요인에 의존하거나 여러 페이지에 걸쳐 사용 가능해야 할 때 더욱 그러하다. 예를 들어, 로그인한 사용자가 어떤 페이지를 처음 방문했을 때만 '환영' 메시지를 보고 이후 방문 시에는 보지 않는 경우를 생각해 보자. 각 페이지가 사용자의 로그인 상태를 직접 관리해야 할까? 그렇게 하면 너무 많은 코드 복사 및 붙여넣기와 중복이 발생할 것이다. 대신, 메시지 처리(설명된 환영 메시지와 더불어 오류 메시지 및 안내 메시지 처리도 포함될 수 있음)를 위한 상태 관리 패턴을 사용한 다음, 메시지가 준비되었을 때 이를 호출하여 받을 수 있다.
상태 관리 라이브러리의 예로는 Vue.js 자바스크립트 프레임워크용 상태 관리 라이브러리인 Pinia가 있다. 앵귤러 프레임워크의 경우 NgRx(리덕스 기반, Signals를 사용하는 경량 대안 포함), NGXS, RxAngular 등 여러 커뮤니티 옵션이 존재한다. 리덕스는 위에서 언급한 프레임워크나 다른 뷰 라이브러리와 함께 사용할 수 있는 범용 상태 관리 라이브러리이지만, 리액트 라이브러리와 함께 매우 흔히 사용된다. 리덕스 문서에서 언급하듯이, 이러한 상태 관리 라이브러리 중 상당수는 가볍고 서로 대체될 수 있다. 또한 인터페이스 구성 요소(양식 필드, 버튼, 메시지 등)가 애플리케이션의 중앙 집중식 데이터 스토어에서 새로운 변경 사항을 청취하는 발행-구독 모델을 기반으로 직접 구축하는 것도 가능하다.
