# 메모리 무결성 강제

---

메모리 무결성 강제(영어: Memory Integrity Enforcement)는 하드웨어의 직접적인 지원을 통해 소프트웨어의 메모리 안전성을 근본적으로 강화하는 컴퓨터 보안 기술 패러다임이다.
이 기술의 핵심 목표는 메모리 할당의 논리적 경계를 물리적인 하드웨어 수준에서 실시간으로 검사하여, C나 C++과 같은 메모리 비안전 언어에서 고질적으로 발생하는 버퍼 오버플로 및 Used-After-Free와 같은 메모리 손상 취약점을 원천적으로 차단하는 데 있다. 이 기술은 주로 프로세서 아키텍처 수준에서 구현되며, 가장 대표적인 예시는 ARM 아키텍처에서 개발한 메모리 태그 확장(Memory Tagging Extension, MTE) 기술이다. MTE는 기존의 소프트웨어 기반 방어 기법(예: 주소 공간 배치 난수화(ASLR), 스택 카나리)들이 제공하는 확률적 방어를 넘어, 결정론적이고 즉각적인 오류 탐지를 가능하게 한다.

개요
전통적으로 메모리 안전성 문제는 운영 체제나 컴파일러 단에서 소프트웨어적인 기법으로 해결하려는 시도가 주를 이루었다. 그러나 이러한 기법들은 회피 공격에 취약하거나 상당한 성능 저하를 유발하는 한계가 명확했다. 하드웨어 기반 메모리 무결성 강제는 CPU가 메모리에 접근하는 모든 개별 연산을 직접 검증하는 방식을 채택한다. 이로써 성능 저하를 최소화하면서도, 기존에는 불가능했던 수준의 강력하고 포괄적인 보안을 제공할 수 있게 되었다. 공격자는 메모리 손상 버그를 이용해 인접한 데이터 구조를 덮어쓰거나, 해제된 메모리를 재사용하여 프로그램의 실행 흐름을 제어하거나 민감 정보를 탈취한다. 이 기술은 메모리 주소와 함께 암호학적으로 안전한 소규모 '태그(tag)' 정보를 활용하여, 특정 포인터가 오직 그 포인터에 할당된 메모리 영역만을 정확히 가리키도록 강제한다. 만약 포인터에 부여된 태그와 해당 포인터가 접근하려는 메모리 영역의 태그가 일치하지 않을 경우, 하드웨어는 즉시 예외(exception)를 발생시켜 공격 시도를 무력화하고 잠재적인 피해를 사전에 방지한다.

핵심 기술
메모리 태그 확장 (MTE) 메모리 무결성 강제의 가장 널리 알려진 구현체는 ARMv8.5-A 아키텍처에서 도입된 메모리 태그 확장(MTE)이다. MTE의 구체적인 동작 원리는 다음과 같다.

태그 할당 및 그래뉼(Granule): 메모리 할당자(예: malloc)가 특정 크기의 메모리 블록을 할당할 때, 4비트의 랜덤 태그를 생성한다. 이 태그는 두 곳에 저장된다. 첫째는 해당 메모리 블록을 가리킬 포인터의 최상위 비트(top bits)이며, 둘째는 실제 물리 메모리(DRAM)에 별도로 마련된 '태그 저장 공간'이다. MTE는 16바이트 크기의 '그래뉼(granule)' 단위로 메모리를 관리하며, 각 그래뉼마다 태그가 할당된다. 즉, 64바이트 메모리를 할당하면 4개의 연속된 그래뉼이 모두 동일한 태그를 갖게 된다.
태그 검증: 프로세서가 포인터를 통해 메모리에 접근(읽기 또는 쓰기)할 때마다, 메모리 컨트롤러는 포인터 주소의 상위 비트에 저장된 태그와, 접근하려는 물리 메모리 주소에 매핑된 태그 저장 공간의 태그를 자동으로 비교한다.
오류 처리: 두 태그가 일치하지 않으면, 하드웨어는 즉각적인 오류를 감지하고 CPU에 예외 신호를 보낸다. 운영 체제는 이 예외를 수신하여 보안 정책에 따라 해당 프로세스를 강제 종료시키거나, 디버깅을 위한 상세 정보를 기록할 수 있다.

버퍼 오버플로 탐지 예시
프로그래머가 char buffer[32];를 선언하여 32바이트 버퍼를 요청한다.
메모리 할당자는 32바이트(16바이트 그래뉼 2개)를 할당하고, 포인터 buffer와 이 두 그래뉼에 태그 0b1010을 부여한다. 바로 인접한 다음 그래뉼에는 다른 태그(예: 0b0011)가 부여되어 있다.
프로그램이 buffer[16]에 데이터를 쓰는 경우, 포인터의 태그(0b1010)와 메모리의 태그(0b1010)가 일치하므로 정상적으로 처리된다.
만약 악의적인 입력으로 인해 buffer[32]에 쓰기를 시도하면(버퍼 오버플로 발생), 이는 세 번째 그래뉼에 접근하는 행위가 된다.
하드웨어는 포인터의 태그(0b1010)와 세 번째 그래뉼의 태그(0b0011)가 불일치함을 감지하고 즉시 예외를 발생시켜 프로세스를 중단시킨다.
MTE는 두 가지 주요 동작 모드를 제공하여 시스템 설계자가 보안 수준과 성능 사이에서 균형을 맞출 수 있도록 한다.

동기 모드 (Synchronous Mode): 모든 메모리 접근 시 예외 없이 즉시 태그를 검사한다. 보안성이 가장 높으며, 오류 발생 시 정확한 명령어 위치에서 즉시 프로세스가 중단되어 디버깅이 용이하다.
비동기 모드 (Asynchronous Mode): 태그 검사를 즉시 수행하지 않고 비동기적으로 처리한다. 성능 저하가 거의 없다는 장점이 있으나, 오류가 발생한 시점과 실제 감지되는 시점 사이에 약간의 지연이 발생할 수 있다.

포인터 인증 코드 (PAC)와의 관계
메모리 무결성 강제 기술은 종종 포인터 인증 코드(Pointer Authentication Codes, PAC)와 함께 사용되어 매우 견고한 다층 방어 체계를 구축한다. PAC 역시 ARM 아키텍처에서 도입된 하드웨어 기반 보안 기능으로, 두 기술은 서로 다른 종류의 공격을 방어하며 상호 보완한다.

PAC (제어 흐름 보호): 포인터 값 자체를 암호학적으로 서명하여 보호하는 기술이다. 비유하자면, PAC는 특정 방에 들어갈 수 있는 유효한 열쇠와 같다. 공격자가 스택에 저장된 반환 주소를 변조하여 임의의 코드를 실행하려는 시도(Return-Oriented Programming)를 할 때, CPU는 함수 반환 직전 포인터의 서명을 검증한다. 서명이 올바르지 않으면(즉, 위조된 열쇠이면) 예외를 발생시켜 제어 흐름 탈취를 막는다.
MTE (데이터 접근 보호): 포인터가 가리키는 데이터 영역의 경계를 보호하는 기술이다. PAC를 통과한 유효한 포인터라 할지라도, 이 포인터가 할당된 메모리 영역을 벗어나 데이터를 읽거나 쓰려는 시도를 막는다. 이는 방 안에 들어온 후, 허가된 가구만 만질 수 있도록 감시하는 경비원과 같다.
PAC가 프로그램의 의도된 실행 흐름을 보장하고, MTE가 그 흐름 내에서 데이터의 공간적·시간적 무결성을 보장함으로써, 공격자는 제어 흐름과 데이터 영역 양쪽에서 강력한 저항에 부딪히게 된다.

도입 과제 및 고려사항
하드웨어 기반 메모리 무결성 강제는 강력한 보안을 제공하지만, 시스템 전반에 도입하기 위해서는 몇 가지 고려사항이 있다.

성능 및 메모리 오버헤드: 동기 모드는 모든 메모리 접근을 검사하므로 미세한 성능 저하가 발생할 수 있다. 또한, 각 16바이트 그래뉼마다 태그를 저장하기 위한 추가적인 메모리 공간이 필요하며, 이는 전체 DRAM 용량의 약 3%에 해당한다.
소프트웨어 생태계 호환성: 이 기술을 완벽하게 활용하기 위해서는 운영 체제 커널, 메모리 할당자, 컴파일러, 디버거 등 시스템 소프트웨어 스택 전반이 MTE를 지원하도록 수정되어야 한다. 태그를 인식하지 못하는 레거시 코드는 포인터의 상위 비트를 다른 용도로 사용하여 태그를 손상시킬 수 있으며, 이는 정상적인 동작에서 오류(false positive)를 유발할 수 있다.
제한된 태그 공간: 현재 MTE 표준의 태그는 4비트로, 16개의 고유한 값만 가질 수 있다. 이는 공격자가 우연히 올바른 태그를 추측할 확률(1/16)이 존재함을 의미한다. 또한, 해제된 메모리가 새로운 할당에 재사용될 때 같은 태그가 부여될 경우(태그 충돌), 시간적 메모리 오류(use-after-free)를 탐지하지 못할 가능성이 있다. 이는 확률적인 방어이며, 태그 공간의 크기가 보안 강도에 직접적인 영향을 미친다.

구현 및 적용
이러한 하드웨어 기반 메모리 무결성 기술은 구글의 안드로이드 운영 체제를 포함한 최신 모바일 플랫폼에서 점차 핵심 보안 기능으로 자리 잡고 있다. 운영 체제 개발사들은 커널 코드와 핵심 시스템 라이브러리에 우선적으로 MTE를 적용하여 가장 민감한 영역을 보호하고, 앱 개발자들에게도 이 기능을 활성화할 수 있는 옵션을 제공하여 생태계 전반의 메모리 안전성을 높이고 있다. JIT (Just-in-Time) 컴파일과 같이 메모리에 쓰기(W)와 실행(X) 권한이 동시에 필요한 특수한 환경에서는, PAC를 이용해 JIT 코드 영역으로의 진입 포인터를 인증하는 등 추가적인 완화 조치가 함께 적용되어 보안 공백을 최소화한다.
